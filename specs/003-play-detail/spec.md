# Feature Specification: 戯曲詳細ページ

**Feature Branch**: `003-play-detail`
**Created**: 2026-03-17
**Status**: Draft

## Assumptions

- 戯曲本文の表示形式はMVPではプレーンテキスト（整形済み）で表示する。将来的にPDFや専用リーダー形式への移行を想定し、本文データは形式に依存しない構造で保持する。
- 戯曲データは初期段階では管理者がDB直接投入またはシード投入する（投稿エディタはスコープ外）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 戯曲の作品情報を確認する (Priority: P1)

ユーザーが一覧ページから気になる戯曲をクリックし、作品の詳細情報（タイトル、執筆者、あらすじ、上演時間、出演人数、ジャンル）を確認できる。上演を検討するための判断材料を得られる。

**Why this priority**: 一覧から個別作品への遷移はサイトの基本フロー。作品情報の確認なしに上演許可申請はできない。

**Independent Test**: 一覧ページのカードをクリックし、詳細ページに作品情報が正しく表示されることを確認。

**Acceptance Scenarios**:

1. **Given** 一覧ページで戯曲カードが表示されている, **When** カードをクリックする, **Then** 詳細ページに遷移し、タイトル・執筆者名・あらすじ・上演時間・出演人数（男/女/不問の内訳）・ジャンルが表示される
2. **Given** 詳細ページが表示されている, **When** 執筆者名をクリックする, **Then** 執筆者のプロフィールページに遷移する
3. **Given** 未ログインのユーザー, **When** 詳細ページにアクセスする, **Then** 作品情報は閲覧できる

---

### User Story 2 - 戯曲本文を読む (Priority: P1)

ユーザーが詳細ページで戯曲の本文を読める。セリフ、ト書き、登場人物一覧などが読みやすく整形表示される。

**Why this priority**: 本文を読めなければ上演作品の選定ができない。サイトのコアバリュー。

**Independent Test**: 詳細ページで本文セクションに戯曲テキストが表示され、スクロールで全文読めることを確認。

**Acceptance Scenarios**:

1. **Given** 詳細ページが表示されている, **When** 本文セクションを表示する, **Then** 戯曲本文がプレーンテキストとして整形表示される
2. **Given** 長い戯曲の本文が表示されている, **When** スクロールする, **Then** 全文を通して読める
3. **Given** モバイル端末でアクセスしている, **When** 本文を読む, **Then** 画面幅に合わせて読みやすく表示される

---

### User Story 3 - 上演許可申請への導線 (Priority: P1)

ユーザーが詳細ページから直接、上演許可申請に進める。上演料の情報も詳細ページで確認できる。

**Why this priority**: 詳細ページは上演許可申請へのコンバージョンポイント。明確な導線が必要。

**Independent Test**: 詳細ページに「上演許可を申請する」ボタンが表示され、クリックで申請フローに遷移することを確認。

**Acceptance Scenarios**:

1. **Given** ログイン済みユーザーが詳細ページを閲覧している, **When** 「上演許可を申請する」ボタンを押す, **Then** 上演許可申請フォームに遷移する
2. **Given** 詳細ページが表示されている, **When** 上演料情報セクションを確認する, **Then** 上演料（無料の場合は「無料」）が表示される
3. **Given** 未ログインユーザーが「上演許可を申請する」ボタンを押す, **When** ボタンをクリック, **Then** ログイン画面にリダイレクトされ、ログイン後に申請フォームに戻る

---

### User Story 4 - 執筆者プロフィール表示 (Priority: P2)

ユーザーが執筆者のプロフィールページにアクセスし、その執筆者の他の作品一覧を確認できる。

**Why this priority**: 気に入った執筆者の他の作品を探す動線。コンテンツ回遊に重要。

**Independent Test**: 執筆者プロフィールページに執筆者情報と作品一覧が表示されることを確認。

**Acceptance Scenarios**:

1. **Given** 詳細ページで執筆者名をクリックした, **When** 執筆者プロフィールページに遷移する, **Then** 表示名・自己紹介・プロフィール画像と、その執筆者の公開作品一覧が表示される
2. **Given** 執筆者が複数の作品を公開している, **When** プロフィールページの作品一覧を確認する, **Then** 全公開作品がカード形式で表示される

---

### Edge Cases

- 存在しない戯曲IDにアクセスした場合 → 404ページを表示
- 非公開（下書き）の戯曲に直接URLでアクセスした場合 → 執筆者本人のみ閲覧可能、それ以外は404
- 本文が極端に長い場合（10万文字以上） → 表示パフォーマンスに影響がないようページ内セクション分割を検討
- 本文データが未投入の戯曲 → 「本文は準備中です」と表示

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 戯曲詳細ページに作品メタデータ（タイトル、執筆者名、あらすじ、上演時間、出演人数内訳、ジャンル）を表示する
- **FR-002**: System MUST 戯曲本文をプレーンテキストとして整形表示する
- **FR-003**: System MUST 上演料情報を表示する（金額または「無料」）
- **FR-004**: System MUST 「上演許可を申請する」ボタンを表示する
- **FR-005**: System MUST 未ログインユーザーが申請ボタンを押した場合、ログイン画面にリダイレクトし、ログイン後に元の詳細ページに戻す
- **FR-006**: System MUST 執筆者名クリックで執筆者プロフィールページに遷移できる
- **FR-007**: System MUST 執筆者プロフィールページに表示名・自己紹介・公開作品一覧を表示する
- **FR-008**: System MUST 未ログインユーザーにも詳細ページと本文を公開する
- **FR-009**: System MUST 閲覧数をカウントし詳細ページに表示する
- **FR-010**: System MUST 存在しないまたは非公開の戯曲へのアクセスに404を返す
- **FR-011**: System MUST SEO対応のメタタグ（OGP、title、description）を動的に設定する

### Key Entities

- **Play（戯曲）**: 002-play-listingで定義済み。本文テキストフィールドを追加。上演料（金額、通貨）、上演料無料フラグ。
- **User（執筆者）**: 001-user-authで定義済み。プロフィールページとして公開される。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 詳細ページが2秒以内に表示される
- **SC-002**: 本文表示が3秒以内にレンダリング完了する（10万文字以下の作品）
- **SC-003**: 詳細ページから上演許可申請への遷移率を計測できる
- **SC-004**: モバイル端末で本文が読みやすいフォントサイズ・行間で表示される
- **SC-005**: 検索エンジンから個別作品ページにランディングできる（SEO）
