# Feature Specification: 執筆者ダッシュボード

**Feature Branch**: `005-author-dashboard`
**Created**: 2026-03-17
**Status**: Draft

## Assumptions

- 全ユーザーが同一ロールのため、ダッシュボードは全ログインユーザーに提供される。
- 作品を持たないユーザーのダッシュボードでは「まだ作品がありません」と表示し、将来の投稿機能への導線を示す。
- 戯曲投稿エディタはスコープ外のため、作品管理は閲覧・編集（メタデータのみ）・公開/非公開切り替えに限定する。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ダッシュボード概要の確認 (Priority: P1)

執筆者がログイン後、ダッシュボードで自分の活動状況を一目で把握できる。作品数、総閲覧数、未対応の上演許可申請数、売上情報がサマリーとして表示される。

**Why this priority**: ダッシュボードの第一印象。ログイン後に最も頻繁にアクセスする画面。

**Independent Test**: ダッシュボードにアクセスし、各種サマリー数値が正しく表示されることを確認。

**Acceptance Scenarios**:

1. **Given** 作品を持つログイン済みユーザー, **When** ダッシュボードにアクセスする, **Then** 以下のサマリーが表示される：公開作品数、総閲覧数、未対応申請数、今月の売上
2. **Given** 未対応の上演許可申請がある, **When** ダッシュボードを表示する, **Then** 未対応申請数がバッジまたはハイライトで目立つように表示される
3. **Given** 作品を持たないユーザー, **When** ダッシュボードにアクセスする, **Then** 「まだ作品がありません」と表示され、作品投稿への案内が表示される

---

### User Story 2 - 作品一覧の管理 (Priority: P1)

執筆者が自分の作品一覧を確認し、各作品のメタデータ編集、公開/非公開の切り替えができる。

**Why this priority**: 作品管理はダッシュボードの中核機能。

**Independent Test**: 作品一覧が表示され、公開/非公開の切り替えが反映されることを確認。

**Acceptance Scenarios**:

1. **Given** ダッシュボードにアクセスした, **When** 「作品管理」セクションを開く, **Then** 自分の全作品が一覧表示される（公開/非公開ステータス、閲覧数、申請数付き）
2. **Given** 作品一覧が表示されている, **When** 作品の「編集」ボタンを押す, **Then** メタデータ（タイトル、あらすじ、上演時間、出演人数、ジャンル、上演料）を編集できる
3. **Given** 公開中の作品がある, **When** 「非公開にする」を押す, **Then** 作品が一覧・検索から非表示になる（既存の許可済み申請には影響しない）
4. **Given** 非公開の作品がある, **When** 「公開する」を押す, **Then** 作品が一覧・検索に表示される

---

### User Story 3 - 上演許可申請の管理 (Priority: P1)

執筆者がダッシュボードから自分の作品に対する上演許可申請を一覧で確認し、承認・却下の操作を行える。

**Why this priority**: 004-performance-permissionの執筆者側操作画面。申請管理のないダッシュボードは機能しない。

**Independent Test**: 申請一覧が表示され、承認/却下操作が正しくステータスに反映されることを確認。

**Acceptance Scenarios**:

1. **Given** ダッシュボードにアクセスした, **When** 「申請管理」セクションを開く, **Then** 自分の全作品に対する申請がステータス別（申請中/承認済み/許可済み/却下/期限切れ）で一覧表示される
2. **Given** 「申請中」の申請がある, **When** 申請の詳細を開く, **Then** 申請内容（団体名、公演日程、会場等）が全て確認でき、承認/却下ボタンが表示される
3. **Given** 申請の詳細を確認した, **When** 「承認」を押す, **Then** 004-performance-permissionのUS2の通り承認フローが実行される
4. **Given** 申請一覧が表示されている, **When** ステータスでフィルタする, **Then** 選択したステータスの申請のみ表示される

---

### User Story 4 - 売上・決済履歴の確認 (Priority: P2)

執筆者が上演料の売上履歴と受取金額を確認できる。

**Why this priority**: 収益の把握は執筆者のモチベーションに直結するが、初期は取引数が少ないためP2。

**Independent Test**: 売上履歴ページに過去の決済が一覧表示され、合計金額が正しいことを確認。

**Acceptance Scenarios**:

1. **Given** ダッシュボードにアクセスした, **When** 「売上」セクションを開く, **Then** 月別の売上サマリー（総額、手数料、受取額）が表示される
2. **Given** 売上セクションが表示されている, **When** 決済履歴一覧を確認する, **Then** 各決済の作品名、申請者名、決済日、金額、手数料、受取額が表示される
3. **Given** まだ売上がない, **When** 売上セクションを開く, **Then** 「まだ売上はありません」と表示される

---

### User Story 5 - Stripeアカウント連携管理 (Priority: P1)

執筆者がダッシュボードからStripe Expressアカウントの連携・連携状態の確認ができる。

**Why this priority**: 有料作品の決済に必須。ダッシュボードからの連携導線が必要。

**Independent Test**: Stripe連携ボタンからオンボーディングが開始され、連携ステータスが反映されることを確認。

**Acceptance Scenarios**:

1. **Given** Stripe未連携のユーザー, **When** ダッシュボードの「Stripe連携」セクションを確認する, **Then** 「未連携」と表示され、「Stripeアカウントを連携する」ボタンが表示される
2. **Given** 「Stripeアカウントを連携する」を押した, **When** Stripe Expressオンボーディングが完了する, **Then** ステータスが「連携済み」に変わる
3. **Given** Stripe連携済みのユーザー, **When** ダッシュボードを確認する, **Then** 「連携済み」と表示され、Stripeダッシュボードへのリンクが表示される

---

### User Story 6 - 通知一覧 (Priority: P2)

執筆者が上演許可申請や決済に関する通知をダッシュボード上で確認できる。

**Why this priority**: メール通知の補完。ダッシュボード上でも確認できると便利だが、メールで代替可能。

**Independent Test**: 通知一覧に過去の通知が時系列で表示されることを確認。

**Acceptance Scenarios**:

1. **Given** ダッシュボードにアクセスした, **When** 「通知」セクションを開く, **Then** 新規申請、承認/却下結果、決済完了などの通知が時系列で表示される
2. **Given** 未読の通知がある, **When** ダッシュボードにアクセスする, **Then** 未読件数がヘッダーのベルアイコンにバッジ表示される
3. **Given** 通知をクリックした, **When** 該当の申請詳細に遷移する, **Then** 通知が「既読」になる

---

### Edge Cases

- 大量の作品（100件以上）を持つ執筆者 → ページネーションと検索機能で対応
- 大量の申請（100件以上） → ステータスフィルタとページネーションで対応
- Stripe連携が途中で中断された場合 → 「連携未完了」ステータスで再試行を促す
- 売上データの通貨 → 日本円（JPY）固定

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST ログイン済みユーザーにダッシュボードを提供する
- **FR-002**: System MUST ダッシュボード概要にサマリー情報を表示する（公開作品数、総閲覧数、未対応申請数、今月の売上）
- **FR-003**: System MUST 作品一覧を表示し、各作品のステータス・閲覧数・申請数を表示する
- **FR-004**: System MUST 作品メタデータの編集機能を提供する（タイトル、あらすじ、上演時間、出演人数、ジャンル、上演料）
- **FR-005**: System MUST 作品の公開/非公開切り替え機能を提供する
- **FR-006**: System MUST 上演許可申請の一覧をステータス別に表示する
- **FR-007**: System MUST 申請一覧のステータスフィルタ機能を提供する
- **FR-008**: System MUST 申請詳細の表示と承認/却下操作を提供する
- **FR-009**: System MUST 月別売上サマリーと決済履歴一覧を表示する
- **FR-010**: System MUST Stripe Expressアカウントの連携機能を提供する
- **FR-011**: System MUST Stripe連携ステータスを表示する
- **FR-012**: System MUST 通知一覧を時系列で表示する
- **FR-013**: System MUST 未読通知の件数をバッジ表示する
- **FR-014**: System MUST 作品を持たないユーザーに適切な空状態メッセージを表示する

### Key Entities

- **Notification（通知）**: 受信者（User参照）、通知種別（新規申請/承認/却下/決済完了）、関連申請（PerformancePermission参照）、メッセージ本文、既読フラグ、作成日時

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ダッシュボードが2秒以内に表示される
- **SC-002**: 作品の公開/非公開切り替えが即座に反映される
- **SC-003**: 未対応申請に対する平均応答時間を把握できる
- **SC-004**: 執筆者が売上の全体像を1画面で把握できる
