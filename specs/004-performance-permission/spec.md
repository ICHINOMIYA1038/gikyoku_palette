# Feature Specification: 上演許可申請

**Feature Branch**: `004-performance-permission`
**Created**: 2026-03-17
**Status**: Draft

## Assumptions

- 決済はStripe Connect（Expressアカウント）を使用し、執筆者への直接送金（プラットフォーム手数料5%控除後）を実現する。
- 有料作品を持つ執筆者はStripe Expressアカウントを連携する必要がある。Stripeが用意する簡易オンボーディングフォームで登録するため、執筆者の負担は最小限。
- 無料作品の場合はStripe連携不要で、承認のみで上演許可が成立する。
- 上演許可は「1公演（公演期間）につき1申請」を基本単位とする。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 上演許可を申請する (Priority: P1)

上演希望者（劇団・演劇部など）が、戯曲の詳細ページから上演許可申請フォームに必要情報を入力して申請を送信できる。

**Why this priority**: サイトの収益モデルの根幹。このフローなしにプラットフォームの価値は成立しない。

**Independent Test**: 申請フォームに情報を入力して送信し、申請が「申請中」ステータスで作成されることを確認。

**Acceptance Scenarios**:

1. **Given** ログイン済みユーザーが戯曲詳細ページにいる, **When** 「上演許可を申請する」ボタンを押す, **Then** 申請フォームが表示され、以下の情報を入力できる：団体名、代表者名、公演名、公演日程（開始日〜終了日）、会場名、会場所在地、想定観客数、チケット料金（有料/無料）、上演回数、申請者からのメッセージ
2. **Given** 申請フォームに必要事項を入力した, **When** 送信ボタンを押す, **Then** 申請が「申請中」ステータスで作成され、確認画面が表示される
3. **Given** 申請が送信された, **When** 執筆者のメールアドレス宛に通知が送られる, **Then** 執筆者が新しい申請があることを知ることができる

---

### User Story 2 - 執筆者が申請を承認/却下する (Priority: P1)

執筆者が自分の作品に対する上演許可申請を確認し、承認または却下できる。承認時にメッセージを添えることもできる。

**Why this priority**: 執筆者の権利を守るコア機能。承認フローなしに上演許可は成立しない。

**Independent Test**: 執筆者がダッシュボードから申請を確認し、承認または却下のアクションが正しく反映されることを確認。

**Acceptance Scenarios**:

1. **Given** 新しい上演許可申請がある, **When** 執筆者がダッシュボードで申請内容を確認する, **Then** 申請の全情報（団体名、公演日程、会場、観客数等）が表示される
2. **Given** 執筆者が申請内容を確認した, **When** 「承認」ボタンを押す, **Then** 申請ステータスが「承認済み（決済待ち）」に変わる（有料の場合）。無料作品の場合は「許可済み」になる
3. **Given** 執筆者が申請内容を確認した, **When** 「却下」ボタンを押し却下理由を入力する, **Then** 申請ステータスが「却下」に変わり、申請者に通知される
4. **Given** 執筆者が承認/却下した, **When** メッセージを添える, **Then** 申請者に執筆者のメッセージが表示される

---

### User Story 3 - 上演料の決済 (Priority: P1)

有料作品の場合、執筆者が承認した後に申請者がStripeで上演料を支払い、決済完了後に正式な上演許可が成立する。

**Why this priority**: 収益化の中核。決済完了をもって正式な上演許可となる。

**Independent Test**: 承認後に決済画面が表示され、テスト決済が完了して「許可済み」ステータスに変わることを確認。

**Acceptance Scenarios**:

1. **Given** 申請が「承認済み（決済待ち）」になった, **When** 申請者に通知が送られる, **Then** 申請者が決済ページにアクセスできる
2. **Given** 申請者が決済ページにアクセスした, **When** 上演料と手数料の内訳が表示される, **Then** 上演料、プラットフォーム手数料（5%）、合計金額が明示される
3. **Given** 申請者がStripe決済を完了した, **When** 決済が成功する, **Then** 申請ステータスが「許可済み」に変わり、執筆者と申請者の両方に通知が送られる
4. **Given** 決済が失敗した（カードエラー等）, **When** エラーが発生する, **Then** エラーメッセージが表示され、再試行できる

---

### User Story 4 - 上演許可証の発行 (Priority: P2)

上演許可が成立した後、申請者が上演許可証（PDF）をダウンロードできる。公演時の権利証明として使用する。

**Why this priority**: 法的・実務的な証明書として必要だが、MVPでは簡易的なものでよい。

**Independent Test**: 「許可済み」の申請から許可証PDFをダウンロードし、必要情報が記載されていることを確認。

**Acceptance Scenarios**:

1. **Given** 申請ステータスが「許可済み」である, **When** 申請者が「許可証をダウンロード」ボタンを押す, **Then** 上演許可証PDFがダウンロードされる
2. **Given** ダウンロードされた許可証PDF, **When** 内容を確認する, **Then** 作品名、執筆者名、申請者（団体名）、公演日程、会場、許可日、許可番号が記載されている

---

### User Story 5 - 申請ステータスの追跡 (Priority: P2)

申請者が自分が送った上演許可申請の一覧とステータスを確認できる。

**Why this priority**: 申請後の進捗確認に必要。

**Independent Test**: 申請者が自分の申請一覧を開き、各申請のステータスが正しく表示されることを確認。

**Acceptance Scenarios**:

1. **Given** ログイン済みの申請者, **When** 「マイ申請」ページにアクセスする, **Then** 自分が送った申請の一覧がステータス付きで表示される
2. **Given** 申請一覧が表示されている, **When** ステータスが変更された申請がある, **Then** 最新のステータス（申請中/承認済み/決済待ち/許可済み/却下）が反映されている

---

### User Story 6 - 執筆者のStripeアカウント連携 (Priority: P1)

有料作品を持つ執筆者が、上演料を受け取るためにStripeアカウントを連携できる。

**Why this priority**: 有料作品の決済フローに必須。Stripe Connectのオンボーディングが必要。

**Independent Test**: 執筆者がStripe連携フローを完了し、アカウントが「連携済み」になることを確認。

**Acceptance Scenarios**:

1. **Given** 執筆者がダッシュボードにいる, **When** 「Stripeアカウント連携」ボタンを押す, **Then** Stripe Connectのオンボーディング画面にリダイレクトされる
2. **Given** Stripeオンボーディングが完了した, **When** サイトに戻る, **Then** Stripeアカウントが「連携済み」として表示される
3. **Given** 有料作品に上演許可申請が来た, **When** 執筆者のStripeアカウントが未連携, **Then** 承認前にStripe連携を求めるメッセージが表示される

---

### Edge Cases

- 執筆者が自分の作品に上演許可を申請した場合 → 申請を許可する（自主公演の記録として）
- 申請承認後、決済前に執筆者が作品を非公開にした場合 → 承認済みの申請は有効のまま維持
- 決済完了後に公演が中止された場合 → 返金はサイト外で当事者間対応（FAQ記載）。将来的に返金機能を検討
- 同一作品・同一期間に複数の申請があった場合 → それぞれ独立した申請として処理（排他制御しない）
- Stripeアカウント連携が途中で中断された場合 → 「連携未完了」ステータスで再試行を促す
- 決済の期限 → 承認から30日以内に決済がない場合、申請は自動的に「期限切れ」になる

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 上演許可申請フォームを提供する（団体名、代表者名、公演名、公演日程、会場名、会場所在地、想定観客数、チケット料金区分、上演回数、メッセージ）
- **FR-002**: System MUST 申請ステータスを管理する（申請中→承認済み(決済待ち)→許可済み、または申請中→却下、または承認済み→期限切れ）
- **FR-003**: System MUST 新規申請時に執筆者にメール通知を送る
- **FR-004**: System MUST ステータス変更時に申請者にメール通知を送る
- **FR-005**: System MUST 執筆者が申請を承認または却下できる
- **FR-006**: System MUST 却下時に理由の入力を求める
- **FR-007**: System MUST 有料作品の承認後にStripe Checkoutによる決済フローを提供する
- **FR-008**: System MUST 上演料からプラットフォーム手数料5%を控除した金額を執筆者に送金する（Stripe Connect）
- **FR-009**: System MUST 決済完了後に申請ステータスを「許可済み」に更新する
- **FR-010**: System MUST 無料作品の場合は承認のみで「許可済み」ステータスにする
- **FR-011**: System MUST 「許可済み」の申請から上演許可証PDFをダウンロードできる
- **FR-012**: System MUST 申請者が自分の申請一覧とステータスを確認できる
- **FR-013**: System MUST 執筆者がStripe Connectアカウントを連携できる
- **FR-014**: System MUST 承認から30日以内に決済がない場合、申請を自動的に「期限切れ」にする
- **FR-015**: System MUST Stripe Webhookで決済イベントを処理する
- **FR-016**: System MUST ログイン済みユーザーのみ申請を送信できる

### Key Entities

- **PerformancePermission（上演許可申請）**: 申請者（User参照）、対象戯曲（Play参照）、団体名、代表者名、公演名、公演日程（開始日・終了日）、会場名、会場所在地、想定観客数、チケット料金区分（有料/無料）、上演回数、申請者メッセージ、ステータス、執筆者メッセージ、決済ID（Stripe参照）、上演料金額、手数料金額、許可番号、申請日時、承認/却下日時、決済完了日時
- **StripeAccount（Stripe連携）**: ユーザー（User参照）、StripeアカウントID、連携ステータス（未連携/連携中/連携済み）、連携日時

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 申請フォームの入力から送信完了まで5分以内で完了できる
- **SC-002**: 執筆者が申請受領から承認/却下まで平均3日以内に対応できる（通知の効果）
- **SC-003**: 決済フローが3ステップ以内に完了する（承認通知→決済ページ→支払い完了）
- **SC-004**: 決済成功率が97%以上（Stripeの標準的な成功率）
- **SC-005**: 上演許可証PDFが5秒以内に生成・ダウンロードできる
